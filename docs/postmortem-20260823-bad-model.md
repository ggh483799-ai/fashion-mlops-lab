# Postmortem：评估门禁拦截坏模型事件

> 日期：2026-08-23
> 类型：模型发布前置拦截（未造成线上影响）
> 状态：已闭环

## 一、事件摘要

算法侧提交一个只训练 1 epoch、仅用 5000 样本的服装分类模型（bad.pt），训练曲线显示在收敛，但评估门禁在 merge 前将其拦截：测试集 accuracy 0.6966 vs 基线 0.9204，掉 22.4 个点，远超 0.5 点阈值，判定 FAIL（exit 1）。

## 二、时间线

| 时间 | 事件 |
|---|---|
| 10:21 | train.py / eval.py 完成并通过冒烟（自对比 PASS） |
| 10:34 | 基线模型训练完成（10 epoch 全量，测试集 acc 0.9204） |
| 10:35 | 坏模型（5000 样本 1 epoch）产出，门禁判定 FAIL（acc 掉 22.4 点） |
| 10:35 | ⚠️ 发现异常：同一模型自比退出码为 1（latency 门禁误判） |
| 10:36 | 定位根因：CPU 单张推理 <1ms，p99 受系统负载影响波动 2-4 倍 |
| 10:37 | 修复：预热 3 批 + 改用 mean latency + 阈值 1.2→1.5 |
| 10:38 | 回归验证：基线自评 PASS×2 / 坏模型 FAIL×2，门禁稳定 |

## 三、根因分析（5-Why）

1. 为什么坏模型被卡？→ accuracy 掉 22.4 点，远超阈值
2. 为什么掉这么多？→ 只训 1 epoch + 5000 样本，欠拟合
3. 为什么会提交这种模型？→ 训练侧只看训练集指标，训练 acc 0.66 看起来"在学"
4. 为什么训练侧没发现？→ 缺少统一的评估集验证入口（人工导出权重时漏跑评估）
5. 为什么必须靠门禁兜底？→ 模型质量无法靠 code review 发现，必须自动化指标门禁

**次要问题（latency 误判）**：
1. 为什么自比会 FAIL？→ p99 测量噪声（CPU <1ms 延迟，负载/缓存波动大）
2. 为什么阈值 1.2 太敏感？→ 相对阈值在"绝对值极小"的指标上被放大
3. 怎么修？→ 预热 + mean latency + 1.5 倍阈值

## 四、门禁如何拦截（机制）

- 三项指标：accuracy（质量）/ mean latency（性能）/ 峰值内存（资源）
- 对比对象：基线模型（baseline.pt），不是拍脑袋的绝对阈值
- 拦截动作：任一超阈值 → exit 1 →（后续接 CI 后）PR 无法 merge

## 六、复盘心得（面试可讲）

1. **门禁的价值**：坏模型"训练曲线在收敛"但"评估集现原形"——只有自动化指标门禁能在 merge 前拦住它，人工 review 做不到。
2. **阈值设计是门禁的命门**：固定阈值在噪声指标上会误伤；相对基线 + 预热 + 稳健统计量（mean 而非 p99）是初版正确姿势。
3. **修复过程本身是资产**：这次 latency 误判的排查（自比 FAIL → 怀疑测量方法 → 改统计量）就是"评估门禁踩过坑、会修"的真实故事。
